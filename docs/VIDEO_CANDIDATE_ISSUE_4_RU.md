# Видео-кандидат: одно поручение → проверенная задача

Это локальный Codex skill для репетиции Issue 4, а не опубликованный plugin или новый MCP-сервер. Он предпочитает подключённый официальный Planfix MCP; существующий `kotelkin-planfix-mcp` можно выбрать только как явную альтернативу. Кандидат не переключается между аккаунтами или backend во время записи.

## Установка кандидата и подготовка в Codex

Если у вас уже есть checkout этой ветки, просто откройте его как workspace в Codex и используйте prompt ниже — клонировать повторно не нужно. Иначе, после публикации ветки кандидата в PR, создайте отдельную публичную копию:

```powershell
git clone --branch codex/issue-4-video-candidate https://github.com/AndreiSVetvit/kotelkin-planfix-mcp.git kotelkin-planfix-mcp-video-candidate
```

Откройте созданную папку как workspace в Codex. Проектный skill находится в `.agents/skills/planfix-owner-task/SKILL.md`; глобальная установка не нужна. Если `$planfix-owner-task` пока не обнаруживается, переоткройте workspace/Codex и проверьте файл; как явный fallback попросите Codex прочитать этот файл и применить его к следующему запросу.

Подключите официальный Planfix MCP к owner-approved безопасному/тестовому аккаунту. Для официального MCP подтверждайте каждый показанный preview отдельно. Если официальный MCP недоступен, сначала явно выберите `kotelkin-planfix-mcp`; для этой альтернативы заранее нужны точный Planfix user ID ответственного и часовой пояс аккаунта. Локально передать требуемый ID допустимо; если значение неизвестно, skill должен спросить, а не угадывать.

## Один демонстрационный запрос

```text
$planfix-owner-task
Создай одну тестовую задачу [DEMO]: подготовить предложение Иванову до завтра. Андрей отвечает. Нужно уточнить требования, посчитать стоимость и отправить мне на проверку. Только оформи задачу, не выполняй работу и не связывайся с клиентом.
```

Разрешите только необходимые уточнения. Если официальный MCP покажет preview, подтвердите его отдельно после проверки. Skill сам выполнит readback и покажет фактические значения; дополнительный prompt для этого не нужен.

Ожидаемый видимый результат: одна задача «[DEMO] Подготовить предложение Иванову», согласованный исполнитель и срок без придуманного времени; в описании три шага:

1. Уточнить требования клиента.
2. Рассчитать стоимость предложения.
3. Отправить черновик владельцу на проверку.

После создания skill должен автоматически показать фактические title, description, assignee, due date/time state и status из readback. Если backend возвращает участников или шаблонные данные, показать их тоже. Незапрошенного участника или другое расхождение нужно назвать, но не удалять автоматически. Шаги в описании не являются чек-листом; не утверждайте, что были созданы checklist/comment, если это не так. Создание задачи может запустить настроенные в аккаунте уведомления или workflow: используйте только аккаунт, где это допустимо, и не обещайте отсутствие уведомлений без подтверждённой настройки.

В исходном прогоне официального MCP было 7 вызовов и около 79 секунд без времени ожидания человеческих подтверждений. Это единичное наблюдение, не benchmark и не обещание скорости или превосходства одного backend.

## Граница кандидата

Skill не меняет публичный контракт MCP и не настраивает credentials. Не добавляйте токены, секреты, account URL или данные реального клиента в репозиторий. Для выбранного backend локально можно использовать необходимые user/task IDs; в демонстрации работайте с синтетической тестовой записью, а на видео маскируйте credentials и реальные чувствительные данные. ID синтетической записи можно показывать, если политика тестового аккаунта это допускает. После одной задачи остановитесь: никаких дополнительных записей или cleanup без отдельного решения владельца.
